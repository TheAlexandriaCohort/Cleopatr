CLI 0.4 defaults to a protected backend: a managed Linux VM on macOS ARM64 (Docker required), or the installed supervisor on native Linux. Cooperative mode requires explicit selection. The Linux backend adds a Rust privileged supervisor, Unix peer authentication, cgroup v2 attribution, namespace isolation, synchronous Landlock/seccomp restrictions, protected state and HTTP/MCP HTTP adapters. Native Linux requires a separately installed supervisor; the managed VM packages it. Neither falls back to an uncontained launch. **The full production objective is not complete.** The kernel compiler currently supports context-free, non-overlapping directory capabilities plus fixed `withinWorkspace` file predicates and individual executable grants, not arbitrary per-operation Cedar predicates. TLS inspection, complete content/exec audit events, expanded database protocol coverage, broader compatibility and independent security review remain required. CLI 0.6 adds the eight actions described in [enclave action coverage](ENCLAVE_ACTIONS.md). See [Linux harness design, coverage, installation and release gates](LINUX_HARNESS.md) for exact limits and reproducible kernel tests.

The private hosted portal is usable for policy authoring, simulation, direct policy publishing, and offline bundle distribution. Automatic online CLI sync is verified against the local web application. Production online sync needs a compatible machine-authentication endpoint outside the owner-only browser gateway.

CLI 0.5.0 follows effective policy modes by default. `--audit` explicitly overrides all policy blocking for one invocation (including inherited Enforce), records supported adapter denials as `ALLOWED_AUDIT`, and retains the Linux enclave and its catalog/protocol restrictions. Stored Environment modes and GUI inheritance locks are unchanged. Per-operation filesystem/process decision telemetry remains incomplete.

CLI 0.5.1 forwards opaque CONNECT tunnels only when the entire effective session is Audit. The protected worker derives that eligibility from the signed Environment policies or the explicit audit override. Enforced and mixed sessions retain the inspection requirement. TLS verification stays with the client; captured Cedar facts cover the CONNECT destination only, not encrypted request paths/bodies or inner MCP/database operations.

CLI 0.6 adds synchronous `process.signal`, `process.privilege_attempt`, `file.metadata`, `network.listen`, `dns.query`, `database.connect`, `database.query` and `database.transaction` handling. Supported operations honor Environment policy modes and record assessed inputs. Mandatory privilege/isolation limits and unsupported protocol features still fail closed in Audit. See [setup, tested coverage and exact limits](ENCLAVE_ACTIONS.md).
